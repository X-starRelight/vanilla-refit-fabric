# 模组兼容性说明

本文档记录本模组（vanilla_refit_fabric）与其它模组交互时的已知行为、已做的兼容处理、
以及尚未完全确认的潜在冲突。排查用的调试日志以 `[VR-调试]` 开头，出现在游戏日志里，
只在使用对称之杖放置/破坏堆叠半砖时打印，量很小。

## 机械动力（飞跃版 Create-Fly）——对称之杖

- 兼容层通过反射接入（`CreateSymmetryCompat`），机械动力不在时静默失效；
  若机械动力升级后接口变化，日志会出现一条 "对称之杖兼容反射失败" 警告并关闭该兼容。
- 放置侧：组合半砖（无对应物品）与"同材质堆叠挡死镜像格"两种情况由本模组补位镜像，
  生存模式按语义消耗一份新填的半砖。
- 破坏侧：本模组接管组合半砖破坏时机械动力的拆除钩子不会触发，镜像格由兼容层自己拆/重建。

## KleeSlabs（只挖双层半砖一半）

**机制**：KleeSlabs 挂在 Fabric 破坏事件（`destroyBlock` HEAD，priority 1000）上。
玩家挖双层半砖（原版 DOUBLE，含本模组注入 MODE 后的竖放 DOUBLE）时，它先于本模组执行：
自行拆一半（DOUBLE 换成同方块单半砖、自己发掉落）并**取消**原版破坏。

**影响**：本模组的破坏接管（priority 1100）设计上"事件被取消就让位"，于是
"对称之杖镜像联动"整条链不会运行——表现为潜行挖掉一半后对称那边毫无反应。

**已做兼容**（`ServerPlayerGameModeBreakCaptureMixin` + `ServerPlayerGameModeMixin`）：
破坏入口以 priority 100 先抓取被挖方块的原始状态快照；破坏被取消时对比快照，
若发现"原本是 DOUBLE、现在已变成同方块单半砖"（即 KleeSlabs 类模组做了半拆），
则补上镜像侧联动：镜像格拆掉 → tick 末尾重建保留的那半 → 掉落被拆的那半。
掉落语义与本模组自己半拆一致（宽松工具判定）；KleeSlabs 自己负责源格掉落，双方不重复。

**注意**：此判定不依赖 KleeSlabs 的具体实现，任何"取消破坏事件并自己拆一半"的模组都会
被同样补偿；而保护类取消（方块原地不动）不会触发补偿，照旧让位。

## 保护/领地类模组（openpartiesandclaims、领地插件等）

若此类模组取消了破坏事件（方块未被替换），本模组完全让位：不做半拆、不做镜像联动。
这是有意为之——保护插件说不让挖就不挖，镜像那边也不该动。

## 尚已确认修复的现象（2026-10-18）

- 对称之杖放置组合竖台阶时镜像格短暂闪默认石头材质：已修复。原因链是镜像格
  依赖服务端落位包，客户端预测若未即时拿到方块实体会先按"无材质"渲染石头占位。
  现有机制：客户端预测落位（`predictMirror`）+ 方块实体兜底补建
  （`MixedSlabBlockEntity.ensure`，只对组合半砖生效，原版 DOUBLE 无方块实体不受影响）。
- 放置/破坏堆叠半砖（正/竖/组合）闪空：随 KleeSlabs 兼容与上述修复一并消失，
  用户实测确认（日志见 `[VR-调试]` 全链路记录：预测→登记→落位→收包→破坏登记→半拆收尾→重建）。
- `[VR-调试]` 日志保留：仅在对称之杖放置/破坏堆叠半砖时打印，量极小，便于日后排查。
